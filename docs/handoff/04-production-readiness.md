# NearSoul — что должно быть в production

Версия 2026-10-18. Сейчас работает **альфа** для друзей. Этот документ перечисляет всё, что обязательно сделать до закрытой беты и публичного запуска. Код для большинства пунктов уже есть; не хватает аккаунтов, ключей, решений и проверок.

Легенда: 🔴 блокирует запуск · 🟠 нужно до публичного запуска · 🟢 желательно.
«Кто»: О = основатель, Р = разработчик/агент, Ю = юрист.

---

## 1. Аккаунты и ключи, которые должен создать основатель

Агент никогда не создаёт аккаунты и не вводит пароли или ключи за основателя.

## 2. Конфигурация production (Render)

| Переменная | Значение в production |
|---|---|
| APP_ENV | `production` (staging для предрелизных проверок) |
| EMAIL_PROVIDER | `brevo` или `resend` (сервер откажется стартовать с `screen`) |
| STORAGE_DRIVER | `s3` |
| DAILY_SET_SIZE | `15` (или решение основателя) |
| PAYWALL_ENABLED | `false` в закрытой бете, `true` после решения о ценах |
| INVITE_ONLY | `true` в закрытой бете |
| JWT_SECRET | новый случайный (≥ 32 символа), не как в альфе |
| SOUL_TALK_ENABLED | только после пунктов §4 |
| VAPID_* | новые ключи для production |
| ADMIN_BOOTSTRAP_EMAIL | email основателя (затем убрать) |
| LAUNCH_CITY | город запуска (решение) |

Отдельные базы, хранилища, ключи и проекты Firebase/RevenueCat для staging и production. **Никаких данных альфы в production.**

## 3. Что должно быть отключено в production (проверить!)

Код уже это гарантирует; проверить вручную на staging перед запуском:
- [ ] Демо-профили не создаются (`seed-demo` не запускается; `demoAllowed()` = false).
- [ ] Код входа не показывается на экране; приходит только на email.
- [ ] `POST /v1/billing/test-activate` отвечает отказом.
- [ ] `/v1/alpha/*` отвечают 404 (симулятор локации, отладка движка).
- [ ] Нет бейджа «ТЕСТ», нет тестовой рекламы («Кафе Пример» и др. с `isTest=true` не показываются).
- [ ] Демо не ставят авто-лайки и не отвечают в чатах.
- [ ] Стартовая команда без `seed-demo.ts`.

## 5. Работы разработчика до запуска

### 5.1 Блокирующие 🔴
| # | Работа | Детали |
|---|---|---|
| 1 | Переключить тайлы карты на коммерческого провайдера | `apps/api/src/modules/nearby/tiles.controller.ts`: заменить UPSTREAM и добавить ключ из env; или выключить карту флагом |
| 2 | Подключить Sentry (API + Flutter) с удалением PII | PRD D21 |
| 3 | Staging-окружение, повторяющее production | отдельный Render-сервис и БД |
| 4 | Бэкапы БД + учение по восстановлению (restore drill) | runbook в `docs/runbooks/` |
| 5 | Перенос фото в R2 + проверка подписанных URL | `STORAGE_DRIVER=s3` |
| 6 | Покупки: продукты в App Store / Google Play, связать с RevenueCat, проверить покупку + восстановление в песочнице | `PRODUCTS` в billing.service.ts, вебхук |
| 7 | Подписанные сборки: Android AAB (ключ подписи), iOS (сертификаты), загрузка в TestFlight / Play internal | CI-секреты |
| 8 | Страница удаления аккаунта и данных доступна вне приложения (требование Google Play) | |
| 9 | Убрать `seed-demo` из стартовой команды production | render.yaml для prod |
| 10 | Модель угроз и проверка безопасности (IDOR, перебор, загрузка файлов, prompt injection) | `docs/threat-model.md` |
| 11 | Нагрузочный тест: 1 000 одновременных пользователей, генерация «Душ дня» | цель: p95 API < 300 мс |

### 5.2 До публичного запуска 🟠
- Redis + BullMQ вместо in-process задач, если инстансов больше одного (CR-2); Socket.IO Redis adapter.
- Нативный push (Firebase) на Android/iOS.
- Вход через Apple и Google.
- Тест «Рядом» на двух реальных телефонах в одном месте.
- Тест PWA на iPhone (Web Push работает только после «На экран Домой»).
- Доступность: экранные читалки, крупный шрифт 200 %, контраст.
- CDN для фото и веба.
- Ретеншн-задачи и автоудаление по срокам (локация 24 ч, Soul Talk 90 дней) — проверить на проде.
- Дашборд метрик для основателя.

### 5.3 Желательно 🟢
- Подписанные десктоп-сборки (Windows MSIX, macOS notarized).
- A/B-тест цен.
- Карточка архетипа для шеринга.
- Обучение ранжирования по исходам «Вы встретились?» (с согласием).

## 7. Финальный чек-лист запуска (go / no-go)

- [ ] Все 🔴 пункты §1, §4, §5.1 закрыты.
- [ ] CI зелёный: API (lint, типы, 254+ тестов, движок ≥ 95 %), Flutter (analyze, test, web, APK).
- [ ] Staging прошёл полный сценарий: вход по email → онбординг → «Души дня» → лайк → матч → чат → отчёт → блок/жалоба → удаление аккаунта.
- [ ] Проверено на телефоне, планшете и компьютере (Chrome, Safari, Firefox).
- [ ] §3 проверен: тестовых функций в production нет.
- [ ] В логах нет координат, ответов, текстов сообщений, Soul Talk (выборочная проверка).
- [ ] Бэкап снят и восстановлен на тестовой базе.
- [ ] Sentry получает ошибки; алерты на падение `/ready`.
- [ ] Юридические тексты опубликованы и стоят в онбординге (новая `TERMS_VERSION`).
- [ ] Основатель дал «go».
